## Lec4 셀레니움

- 실행 검증 불가: 코드 문항은 `verify: { mode: "skip", reason: "셀레니움 …" }`. 코드 빈칸의 허용 답안은 **슬라이드 표기 기준으로 엄격하게**(후보 실행 없음 — 토큰 비교로 같은 공백·따옴표 차이만 같은 답)
- 긴 XPath 경로 문자열과 설치 명령(4-1, pip)은 출제하지 않는다(결정 9). XPath 자리는 슬라이드 s.20처럼 `'[실제 XPath 값]'`으로 둔다. 짧은 API(메서드 이름, By 종류)와 정적/동적 페이지 개념은 슬라이드에 있는 것만
- 실행 제외 코드로 실행 결과를 묻지 않는다(웹페이지 내용은 접속 시점마다 다르다)

## Lec5 MySQL

- 슬라이드 스키마·데이터(firstDB, [코드 5-2]~[코드 5-5])를 문항마다 넣고 sql.js로 실행 검증. 준비 스크립트: `firstDB`(전체), `studentCourse`(학생·과목만 — [코드 5-4] 수강 테이블 만들기용), `empty`([코드 5-2]·[코드 5-3] 테이블 만들기용)
- 결과 행 순서는 ORDER BY를 요구하는 문제만 비교
- SQL 빈칸은 키워드(SELECT·FROM·WHERE·GROUP BY·INSERT INTO·VALUES·UPDATE·SET·DELETE 등)·조건식·열 이름·집계 함수 위치에 고르게
- MySQL 전용 문법(CREATE DATABASE·USE·VALUES 안의 DEFAULT·VERSION())은 실행 제외 + 빈칸형·개념형으로만. sql.js와 MySQL 결과가 다를 수 있는 동작(문자열 대소문자 비교·CHAR 길이 초과·외래키 오류 문구)은 실행 결과 문제로 내지 않는다
- "데이터 값은 대소문자를 구별한다"는 "강의 자료에 따르면"으로 묻고 해설에 "(보충) MySQL 8 기본 설정에서는 구별하지 않음"(결정 8)
- MySQL 설치 과정은 최대 2문항(결정 10)

## 문서와 다르게 한 부분

- Lec5 PDF에 ORDER BY가 없어 ORDER BY 빈칸·행 순서 비교 문제는 내지 않았다(PDF 범위만)
- SQL 결과 고르기는 mcq만 지원(보기 = 결과 표 행을 " / ", 값을 ", "로 이은 글자, 행 순서 무시). SQL 오류 검사는 sql.js와 MySQL의 오류가 달라 출제하지 않는다
- 복수 선택 8% 이상은 Lec4~에만 강제 — Lec1~3 보강 지시는 코드 빈칸·작성·결과·mcq 비율만이라 Lec2(6.6%)는 그대로 두었다
