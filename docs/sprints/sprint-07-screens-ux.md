# Sprint 7 — 화면 / UX 구현

## 목표

원본 §3(정보 구조)의 화면을 **과목 → 챕터** 흐름([`multi-subject-design.md`](../multi-subject-design.md) §4)으로 실제 데이터와 연결해 처음부터 끝까지(홈 → 과목 → 챕터 선택 → 퀴즈 → 결과 → 오답노트) 풀 수 있는 앱을 완성한다. 이 시점의 실제 콘텐츠는 OS뿐이지만, 모든 화면은 과목 레지스트리를 순회해서 만들어 데이터 통신 콘텐츠가 추가될 때 화면 코드를 고치지 않게 한다.

## 선행 조건

- Sprint 3(렌더러/채점기), 최소 Sprint 5(Ch02·Ch03 콘텐츠) 완료. Sprint 6 콘텐츠는 완료 전이어도 병행 가능.

## 완료 기준 (DoD)

- 홈에서 과목 → 챕터 선택 → 필터 설정 → 즉시채점/시험 모드 각각으로 퀴즈 완료 → 결과 확인 → 오답노트에서 재응시까지 전체 플로우가 끊김 없이 동작
- localStorage를 비활성화한 브라우저 환경(혹은 모킹)에서도 앱이 에러 없이 동작 (요구사항 §1 "저장소가 막혀 있어도 정상 동작")
- 모바일 뷰포트(375px 기준)에서 모든 화면과 모든 문제 유형이 조작 가능

### 이 문서와 다르게 한 부분

1. **핵심 한 줄 요약**: 대부분 문항에 `summary`가 없어, 없으면 해설의 첫 문장(앞의 "p.N:" 출처 표기는 뗌)을 보여 준다. 해설이 한 문장뿐이면 중복이라 숨긴다(`keyLine`, 테스트 포함).
2. **trace 모바일**: "모바일 입력 대체 동작" 대신, 640px 미만에서 표를 **열 하나 = 카드 하나**로 세로로 쌓는다 — 375px에서 페이지·표 어느 쪽도 가로 스크롤 없음. 넓은 화면은 기존 표.
3. **시험 모드 미응답**: 결과에서는 오답으로 세고 "틀린 문제만 다시 풀기"에도 포함하지만, 학습 기록(`recordAttempt`)·오답노트에는 남기지 않는다(풀지 않은 문제). 미응답을 오답노트에 "미응답"으로 넣는 안(2026-10-05 요청)은 판정 규칙 — Sprint 3 "학습 기록·통계(정답 수, 정답률, 오답노트, ⭐ 달성도)는 완전히 맞음 기준으로만 센다 / 오답이면 오답노트에 쌓인다", multi-subject-design §5, `lib/storage/records.ts` — 와 충돌해 보류(오답노트는 채점된 오답만 담고, 미응답은 채점되지 않음). 넣으려면 규칙 문서와 `WrongRecord` 스키마(백업 형식 포함)를 먼저 바꿔야 한다.
4. **/quiz 쿼리 이름**: 설계 문서의 `exam=1&n=20`, `?session=1` 대신 `star=1&count=20&topics=…&timer=…`, `?session={세션 id}` — [`multi-subject-design.md`](../multi-subject-design.md) §4·§5를 구현에 맞게 고침.
5. **`/stats`**: 이 스프린트 범위 밖이라 안내 문구 그대로(Sprint 8).

### 운영 메모 — dev 서버 오류 (2026-10-05)

`localhost:3000/s/os`의 "Jest worker encountered 2 child process exceptions, exceeding retry limit"는 고아가 된 `next dev`(npm 래퍼만 종료되고 본체는 약 7시간 계속 실행)의 정적 경로 작업자(`/s/[subject]` generateStaticParams)가 두 번 연속 죽은 것이다. 같은 로그에 이후 `write EPIPE` 2,124줄. 시스템 메모리 7.7GB 중 남은 것이 0.1~0.3GB였고 그 사이 `next build`(작업자 7개)를 여러 번 돌려 부담을 키웠다. dev(`.next/dev`)와 build(`.next`)는 서로 다른 폴더에 써서 직접 덮어쓰지는 않았다. dev를 끄고 `.next`를 지운 뒤 `build && start`로 띄우면 재현되지 않음(`/s/os` 200×5, 전체 흐름 오류 0).
