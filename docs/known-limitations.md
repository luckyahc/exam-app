# 알려진 한계

이 앱에서 알고 있으나 고치지 않은(또는 고칠 수 없는) 한계를 한곳에 모았다. 문항을 쓸 때 이 목록의 차이가 정답에 영향을 주지 않도록 규칙(`lib/verify/rules.ts`)과 결정(`docs/ds-question-types.md` §10)으로 막는다. 마지막 정리: 2026-10-07(Sprint 17).

## 실행 엔진 (데이터과학)

| 한계 | 영향 | 대응 |
|---|---|---|
| **sql.js(SQLite)와 MySQL 문법 차이** — 쉼표 조인 뒤 `ON`(SQLite 실행·MySQL 오류), 길이를 넘는 값(`CHAR(2)`에 'c10' — SQLite 저장·MySQL 엄격 모드 오류), 문자열 비교 대소문자(SQLite 구별·MySQL 8 기본 구별 안 함) | SQL 전체 작성형에서 MySQL로는 오류인 답이 정답이 될 수 있다 | 결과 화면에 "MySQL과 문법 차이가 있을 수 있음" 안내. 대소문자만 다른 값으로 채점하는 문제는 내지 않는다(`ds-question-types.md` §11) |
| **MySQL 전용 문법은 실행 불가** — `CREATE DATABASE`·`USE`·VALUES 안의 `DEFAULT`·`VERSION()` | 실행 검증·작성형 불가 | 실행 제외 + 빈칸형·개념형만(결정 8, `rules.ts`가 감지) |
| **Pyodide와 Colab 출력 차이** — 기본 정수가 int32(Colab int64): `dtype`·`itemsize`·`nbytes`·`sys.maxsize`, 메모리 주소(`id()`) | 같은 코드의 출력이 슬라이드와 다르다 | 이런 출력은 결과 고르기·작성형으로 내지 않는다(결정 15, `rules.ts`가 감지). 개념 문제로만 묻고 해설에 플랫폼 차이를 적는다(예: Lec6 [코드 6-4]) |
| **판다스 DataFrame·Series 통째 출력** — 판다스 버전·화면 폭에 따라 정렬·생략(…) 표시가 달라질 수 있다 | 결과 고르기 보기가 환경마다 다를 수 있다 | 결과 고르기는 shape·len·셀 값·`tolist()`·평균으로만. 작성형은 같은 엔진의 모범 답안 출력과 비교해 환경 차이가 없다 |
| **판다스 불러오기 시간** — 추가 약 7.9 MB(넘파이 3.0 + 판다스 4.9), PC 약 9~17초(Python 포함 첫 준비), 휴대폰 30~60초 예상 | 판다스 문제 첫 실행이 느리다 | 버튼을 눌렀을 때만 불러온다(결정 7). 한 번 불러오면 같은 탭에서는 다시 불러오지 않고(Worker 재사용), 파일은 1년 캐시. 페이지를 새로고침하면 Worker는 다시 만들지만 파일은 캐시에서 읽는다 |
| **Python 실행 시간 제한 5초** — Pyodide는 실행 중에 끊을 수 없어 시간이 넘으면 Worker를 통째로 버린다 | 무한 루프 뒤 다음 실행은 엔진을 다시 불러온다(캐시라 내려받기는 없음) | "시간 초과" 오답 처리 |
| **사용자 코드의 네트워크 금지** — `fetch`·`XMLHttpRequest`·`WebSocket` 차단 | 웹 요청 코드는 실행할 수 없다 | 그런 코드는 실행 제외 |
| **휴대폰 메모리** — Python+판다스 엔진은 탭 메모리를 수백 MB 쓴다 | 메모리가 적은 기기에서 브라우저가 탭을 다시 불러올 수 있다(그러면 엔진도 다시 준비) | 판다스는 필요할 때만 불러온다 |

## 실행할 수 없는 코드 (데이터과학)

| 한계 | 대응 |
|---|---|
| **셀레니움**(Lec4) — 실제 브라우저·사이트 접속이 필요 | 모두 실행 제외 + 빈칸형·코드 보기 개념형만 |
| **Colab 전용 명령**(`!pip install`, `from google.colab import …`, 파일 업로드) | 실행 제외(`rules.ts`가 감지) |
| **실제 파일·네트워크가 필요한 코드**(Lec3 CSV·엑셀) | 검증·채점 때 `python.setup`으로 가상 파일을 만든다(같은 내용·인코딩) |
| **난수**(`np.random.randn` 등) | 출력 문제로 내지 않는다(실행마다 다름). 필요하면 고정 값으로 바꾸고 해설에 밝힌다 |

## 채점·콘텐츠

| 한계 | 대응 |
|---|---|
| **코드 빈칸형은 토큰 비교** — 같은 결과가 나오는 다른 표현은 허용 답안(`accept`)에 넣은 것만 정답 | 검증 파이프라인의 후보 규칙 12개가 대체 표현을 찾아 실행으로 확인한 뒤 넣는다(`lib/verify/candidates.ts`) |
| **슬라이드 오류**(인쇄 오류·실행결과가 코드와 다름) | 정답은 실제 실행 결과, 해설에 "(보충)"으로 차이를 적는다(`lib/verify/errata.ts`) |
| **⭐ 시험 포인트 없음(데이터과학)** — 강의 PDF에 필기·인쇄 강조 근거가 없다 | 데이터과학은 ⭐ 필터를 쓰지 않는다(결정 3) |
| **복수 선택은 완전히 맞아야 1점(데이터과학)** | 시험 방식과 같게(결정 6), 화면에 부분 점수 없음 안내 |

## 저장·배포

| 한계 | 대응 |
|---|---|
| **기록은 브라우저 localStorage에만** — 기기·브라우저 사이에 옮겨지지 않고, 사생활 보호 모드·저장소 차단에서는 저장되지 않는다 | 통계 화면의 내보내기/가져오기(JSON)로 옮긴다. 저장소가 막혀도 앱은 동작한다(`safeStorage`) |
| **엔진 파일은 빌드 때 준비** — `prepare-engine`이 빌드 중 휠을 내려받는다(cdn.jsdelivr.net·files.pythonhosted.org, SHA-256 검사) | 내려받기 실패·해시 불일치면 빌드가 실패한다. 실행 시에는 외부 요청이 없다 |
| **Vercel 응답 헤더(Content-Type·캐시)는 배포 후 확인 필요** | `docs/deploy-checklist.md` |
