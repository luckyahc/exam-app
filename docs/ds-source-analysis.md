## 분석 방법

1. `pdfinfo`·`sha256sum`으로 쪽 수·해시를 기록하고, `pdftotext -layout`(쪽별)로 각 쪽 오른쪽 아래에 인쇄된 슬라이드 번호(`N / 전체`)를 읽어 **PDF 쪽 ↔ 슬라이드 번호** 대응표를 만들었다.
2. **274쪽 전부를 110 dpi 이미지로 렌더링해 한 쪽씩 눈으로 봤다**(필기·인쇄 강조·코드 들여쓰기 확인). 애매한 쪽은 300 dpi로 다시 봤다(Lec2 s.16 들여쓰기, Lec6 s.54 표 숫자).
3. 주석 층 확인: `pdftoppm -hide-annotations`로 주석을 뺀 렌더링과 비교해 **주석이 있는 쪽 8개**를 찾았고, PDF 객체를 직접 읽어 종류(FreeText·강조)·작성 시각을 확인했다(§3-2).
4. 코드는 `pdftotext -raw`로 글자를 뽑고 쪽 이미지와 대조해 전사했다(부록 A). 들여쓰기는 이미지 기준으로 복원했다.
5. **실행 검증**(분석용 임시 스크립트, 저장소 밖): 순수 파이썬·CSV·openpyxl·넘파이·판다스 코드는 로컬 Python 3.14.7(numpy 2.5.3, pandas 3.0.6, openpyxl)로, SQL은 SQLite 3.50.4로 실행해 슬라이드 실행결과와 비교했다(§4-3, §5-3). Pyodide 314.0.7(브라우저용 파이썬)도 Node에서 직접 띄워 동작 차이와 로딩 시간을 쟀다(`ds-question-types.md` §3).
