# Sprint 14 — 작성 시 검증 파이프라인 (초안)

> **초안(2026-10-06)** — Sprint 13(실행 엔진) 결과를 반영해 시작할 때 정식 문서로 다듬는다. 근거: [`ds-question-types.md`](../ds-question-types.md) §6-2.

## 목표

데이터과학 문제를 만들 때 정답 코드·테스트·허용 답안을 **실제로 실행해서** 검증하는 파이프라인을 만든다. 빌드(앱 번들)에는 포함하지 않는다.

## 작업 항목 (초안)

- [ ] Vitest + Pyodide(Node)·sql.js로 문제 데이터 검사(Sprint 13 엔진 재사용): 모범 답안이 모든 테스트 통과, `code-blank`의 모든 `accept`를 끼운 코드가 같은 결과, 대표 오답(`wrong`)은 실패
- [ ] **코드 빈칸 허용 답안 규칙(2026-10-06 사용자 결정)**: 허용 답안에는 "실행해서 같은 결과가 나오는 다른 표현"을 **검증 파이프라인으로 찾아** 포함한다(예: `a+=1` / `a=a+1`, `i<=9` / `i<10`, `'cp949'` / `"cp949"`는 토큰 비교로 이미 같음). **슬라이드 표기를 `accept`의 첫 번째 정답으로 둔다**(결과 화면의 "정답" 표시·`answerKey`가 첫 번째 값을 쓴다)
  - 후보 생성: 빈칸 종류별 변형 규칙(복합 대입 ↔ 풀어 쓴 대입, 비교 연산 경계 바꾸기, 괄호 추가 등)으로 후보를 만들고, 빈칸을 채운 전체 코드를 실행해 모범 답안과 결과(표준 출력·변수 값·테이블 상태)가 같은 것만 남긴다
  - 남긴 후보는 사람이 보고 `accept`에 넣는다(자동으로 데이터에 쓰지 않음) — 검사 테스트는 `accept`에 들어간 모든 답이 같은 결과를 내는지 확인
- [ ] 슬라이드 실행결과 대조 기록 `docs/verification/data-science-lecN.md`(일치 / 슬라이드 오류 / 플랫폼 차이 — `ds-source-analysis.md` §4-3의 6건 포함)
- [ ] 무거운 검사(판다스)는 파일을 나누고, 필요하면 별도 스크립트로 분리(Sprint 13 측정값 기준)

## 완료 기준 (초안)

- 일부러 틀린 데이터(정답이 다른 결과를 내는 `accept`, 통과하지 못하는 모범 답안)로 테스트가 실패하는 것을 확인
- 기존 회귀 유지
