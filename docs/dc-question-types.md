## 2. 문제 유형 엔진 보강 — `calc` 입력 (Sprint 9)

데이터 통신 계산은 값의 범위가 넓다(3×10⁸ m/s, 0.75 μm, 0.651 μs, 34,881 bps). 기존 `calc`(숫자 + 허용 오차)를 유지하면서 아래만 보강한다. 새 유형이 아니라 `calc`의 옵션이라 OS 문제에는 영향이 없다.

- **입력 파서**: `34881`, `34,881`, `3e8`, `3×10^8`, `3*10^8`, `3x10^8`·`3X10^8`(영문 x), `0.75e-6`, 가수 없는 `10^6`·`10^-3`을 모두 숫자로 인식(곱셈 기호 앞뒤 공백 허용). 의미가 하나로만 읽히는 형태만 받는다 — 지수 없는 `3x10`, 부호 붙은 `-10^6`(−(10⁶)인지 (−10)⁶인지 갈림), `2^10`처럼 밑이 10이 아닌 거듭제곱, `10 ^6`처럼 `^` 앞뒤 공백은 형식 오류. 해석 불가 입력은 오답이 아니라 "형식 오류" 안내(제출 막음). (2026-10-05 Sprint 9 마무리에서 영문 x·가수 없는 10^n 추가)
- **단위 고정**: 문제마다 정답 단위를 하나로 정해 `unit`에 적고(예: `kbps`, `ms`, `dB`) 입력칸 옆에 표시한다. 단위를 고르게 하는 문제는 `mcq`로 따로 낸다.
- **허용 오차 규칙**: 상대 오차(`relTolerance`) 옵션 추가. 기본은 문제에서 요구하는 반올림 자릿수의 절반. 슬라이드 근사값이 있는 경우(확인 필요 5~7)는 그 값도 정답 범위에 들어가게 오차를 잡는다.
- **풀이 표시**: 해설에 생성기가 만든 단계별 풀이(공식 → 대입 → 결과)를 표시(원본 §4 `calc` 요구사항).

## 3. 생성기 (`lib/sim/data-comm/`)

모두 Ch02. 각 생성기 = 순수 계산 함수 + seed 기반 문제 생성기 + **슬라이드 기준값 Vitest**. 파라미터는 슬라이드 예시와 같은 형태·범위에서만 뽑는다(예: 대역폭은 kHz~MHz, SNR은 슬라이드처럼 `2^k − 1` 꼴을 섞어 log가 깔끔하게 떨어지는 문제와 그렇지 않은 문제를 함께).

| 생성기 | 계산 (슬라이드 공식만) | Vitest 기준값 (슬라이드) | 출제 형태 |
|---|---|---|---|
| `signal` | f = 1/T, T = 1/f; 주기 비율 → 도/라디안; λ = c/f = c·T; 대역폭 = f_max − f_min; peak = √2 × 실효 | 1/6 주기 = 60° = π/3 rad (≈1.046, ±0.002); 빨간빛 4×10¹⁴ Hz → 0.75×10⁻⁶ m; 적외선 3×10¹¹ Hz → 10⁻³ m; 1000~5000 Hz → 4000 Hz; 220 V → 310 V(±1.5) | `calc`, `mcq` |
| `digital` | 비트율 = 쪽 × 줄 × 글자 × 비트; 비트 길이 = 1/비트율 (**문제에 답의 단위(초/μs) 명시**, 해설에 "교재 정의는 거리, 슬라이드 예제는 시간" 한 줄 자동 삽입); r = log2 L; S = N/r | 100·24·80·8 = 1,536,000 bps; 1/1,536,000 = 0.651 μs; 2레벨 r=1, 4레벨 r=2 | `calc` |
| `decibel` | dB = 10 log10(P2/P1); SNR = Ps/Pn; SNR_dB = 10 log10 SNR | 0.5배 → −3 dB(±0.05); 10배 → 10 dB; 100배 → 20 dB; 10 mW/1 μW → 10,000·40 dB | `calc`, `ox`(부호: 감쇠 음수/증폭 양수) |
| `capacity` | Nyquist BitRate = 2B log2 L (비트율·L 역산); Shannon C = B log2(1+SNR); 두 한계 함께(상한 → 선택 비트율 → L) | 20 kHz·265 kbps → log2 L = 6.625, L ≈ 98.7; L=128 → 280 kbps, L=64 → 240 kbps; SNR=0 → 0; 3000 Hz·SNR 3162 → 34,881 bps; 1 MHz·SNR 63 → 6 Mbps, 4 Mbps → L=4 | `calc`, `trace`(두 한계 단계 표) |
| `performance` | 처리량 = 프레임 × 비트 / 시간; 전파 = 거리/속도; 전송 = 크기/대역폭; 지연 = 4요소 합; BDP = 대역폭 × 지연 | 12,000 프레임/분 × 10,000 비트 → 2 Mbps; 12,000 km·2.4×10⁸ m/s → 50 ms; 2500 B·1 Gbps → 0.020 ms; 1 bps×5 s = 5 비트; 5 bps×5 s = 25 비트 | `calc` |
| `pcm` | 표본화율 = 2 × 최고 주파수; 비트율 = 표본화율 × 표본당 비트 | 4000 Hz·8비트 → 8000 표본/s, 64 kbps | `calc` |
| `modulation` | BASK·BPSK B = (1+d)S; BFSK B = (1+d)S + 2Δf; S = N (r=1); AM B = 2B; FM B = 2(1+β)B (β 기본 4); PM B = 2(1+β)B (β는 문제에서 제시) | 공식 자체가 기준(슬라이드에 수치 예제 없음) → d=0, d=1 경계값과 손으로 검산 가능한 정수 예로 테스트하고 이 사실을 테스트 주석에 명시 | `calc`, `match`(방식 ↔ 공식) |
| `multiplexing` | FDM 대역폭 = n × 채널 대역폭 + (n−1) × 보호 대역; 동기식 TDM 링크율 = n × 입력율, 슬롯 = T/n | 5채널·100 kHz·보호 10 kHz → 540 kHz; 입력 3개 → 슬롯 T/3 | `calc` |
| `linkFill` (trace) | 대역폭 b bps, 지연 d s일 때 t초 뒤 링크 안의 비트(1번째 비트의 위치, 채워진 비트 수) | s.49 Case 1 표(1 bps, 5 s: 5초 뒤 5비트), s.50 Case 2 표(5 bps, 5 s: 5초 뒤 25비트) | `trace` |
| `tdmFrame` (trace) | 입력 n줄의 데이터 단위 → 프레임 k의 슬롯 순서 | s.90 그림: A1·B1·C1 → Frame 1, A2·B2·C2 → Frame 2 … (그림의 오른쪽→왼쪽 표기 방향 그대로) | `trace` |

### 만들지 않는 생성기 (슬라이드 근거 부족)

| 후보 | 이유 |
|---|---|
| 메시 토폴로지 링크 수 | 공식이 슬라이드에 없고 "n=5, 10 links"만 있음 → 정적 문제 1~2개로만 (확인 필요 3) |
| 델타 변조 비트열 | 비트 결정 규칙이 글로 없음, 그림만 있음 (확인 필요 8) |
| 전화선 대역폭 ↔ 비트율 비례(4 kHz → 56 kbps) | 공식이 아니라 사례 → 정적 `mcq` |
| 케이블 감쇠 곡선 수치 | 그래프 판독 오차 큼 → `graph`(경향)만 |
