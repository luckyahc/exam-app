## 1 (p1) 가상기억장치 정책 — 잘못된 것 2개 (복수선택)
1) Page fault 발생 시에 필요한 페이지를 메모리로 가져오는 전략을 demand paging이라 함
2) 디스크(가상기억장치)에 있는 페이지를 미리 예측하여 사전에 메모리로 가져오는 전략을 prepaging이라 함
3) 디스크로 swap out 되지 않도록 중요한 페이지들은 프레임에 고정시켜 두는 것을 page locking이라 함
4) 향후 가장 오랫동안 참조되지 않을 페이(지)를 선택하는 페이지 교체 알고리즘을 Optimal policy라 함
5) Paging system에선 placement 전략은 아주 중요한 역할을 함

## 4 (p4) 운영체제 구성요소 — 틀린 것 3개 (복수선택)
1) 커널은 프로세스관리, 가상기억장치, 파일시스템, 네트워크, 프로세서 스케줄링 등의 구성요소를 포함한다.
2) 커널은 가장 중요한 시스템 프로그램들의 집합이다.
3) 운영체제는 크게 커널과 시스템 프로그램으로 구성된다.
4) 커널은 메모리에 로드되는 시간을 줄이기 위해 부팅된 후 응용프로그램의 실행 시 필요할 때 그때 그때 메모리에 로드된다.
5) 커널은 인터럽트 발생에 의해서만 실행될 수 있다.

## 8 (p8) Thrashing — 잘못된 것 3개 (복수선택)
1) 초반에는 시스템 내에 실행할 프로세스 수가 많아질수록 processor가 할 일이 점점 더 많아 processor 이용률이 점점 더 높아짐
2) 한 프로세스에게 주어지는 메모리 량이 점점 더 많이 주어질수록 page fault rate는 급격히 증가함
3) Thrashing이 발생해도 processor는 계속 일하므로 processor 이용률에는 큰 변화가 없음
4) 한 프로세스에게 주어지는 메모리 량이 점점 더 작게 주어질수록 page fault rate는 완만히 감소함
5) 실행할 프로세스 수가 점점 더 많아지면 page fault가 급격히 많이 발생하기 시작함

## 10 (p10) Dynamic memory partitioning(Buddy 제외) — 틀린 것 2개 (복수선택)
1) 가상기억장치의 placement policy로 사용될 수 있다.
2) Best-fit의 경우 가장 적합한 크기의 메모리를 할당하므로 메모리 compaction이 필요 없다.
3) 때때로 memory compaction이 필요하다.
4) Partition들은 크기도 다양하고 개수도 가변적이다.
5) External fragmentation이 발생할 수 있지만 best-fit에서는 발생하지 않는다.

## 14 (p14) 메모리 공유(sharing)의 적절한 예가 아닌 것
1) 여러 프로그램이 동일한 DLL 라이브러리 함수를 사용해도 이 함수 코드는 메모리에 하나만 존재함
2) 2개 이상의 동일한 파워포인트 프로그램이 heap 영역을 공유 영역으로 선언하고 이를 서로 공유할 수 있음
3) 2개 이상의 동일한 아래한글 프로그램이 실행되어도 프로그램 코드는 메모리에 하나만 존재함
4) 하나의 배열을 선언하고 이를 공유 데이타 영역으로 설정하면 여러 프로그램이 이 배열을 공유하여 사용할 수 있음

## 17 (p17) 가상기억장치 프로그램 실행 과정 순서 [보기 잘림]
A) OS는 프로그램 시작 부분을 메모리에 로드한 후 프로그램을 실행함
B) Interrupt가 발생하면 실행 중이던 프로세스를 Blocking 상태로 설정한 후 프로세스의 실행을 중단하고 Disk에게 참조된 페이지를 읽어 들이라고 요청함
C) 디스크는 요청된 페이지를 읽어 메모리에 로드하고 이를 알리기 위해 Disk interrupt를 발생시키며, 그러면 CPU는 현재 실행 중인 프로세스의 실행을 멈추고 interrupt handler를 실행함
D) 스케줄러를 호출하여 다른 프로세스에게 process switch함
E) 디스크에 의해 요청된 페이지가 읽혀지면(Disk Interrupt가 발생하면) 이를 요청한 해당 프로세스의 page table이 수정되고 그 프로세스는 다시 Ready 상태가 됨
F) 프로세스가 실행을 하다가 메모리에 없는 주소를 참조했을 때 page fault(memory fault) interrupt가 발생함
G) 이후 스케줄러가 호출되고 요청된 페이지가 로드된 해당 프로세스(page fault가 발생했던)가 다시 실행을 시작하게 됨 [끝부분 잘림]

## 19 (p19) basic paging system — 옳은 것
1) 프로세스와 실제 메모리를 동일한 크기의 영역으로 분할해 놓은 것을 각각 frames와 pages라 한다.
2) MMU 장치는 논리주소를 실제주소로 변화하며 메모리 protection 기능까지 제공한다.
3) 한 프로그램의 모든 page들은 메모리의 연속된 공간에 배치되어야 한다.
4) 페이지 테이블은 논리주소를 실제주소로 변환하기 위해 필요하며 MMU가 만들고 관리해 준다.
5) 프로세스에서 사용하는 모든 포인트 변수의 주소 값은 실제 메모리 주소이다.

## 20 (p20) 지역성(locality) — 잘못된 것 2개 (복수선택)
1) 이 원리로 인해 미래에 참조되는 영역들을 어느 정도 예측할 수 있음
2) 이 원리를 기반으로 하여 가상기억장치가 설계되었음
3) 참조되는 이런 영역들은 시간이 흐를수록 점점 다른 영역으로 이동함
4) 참조되는 페이지의 개수는 프로그램 초기에는 작지만 시간이 흐름에 따라 계속 해서 늘어남
5) 프로세스는 시점과 상관 없이 항상 프로그램 전체를 골고루 참조함

## 21 (p21) Trap interrupt — 틀린 것
1) 다음에 실행할 명령어가 현재 메모리에 없고 디스크의 가상기억장치에 있는 경우 발생함
2) 프로그램을 다운 받다가 명령어가 깨졌는데 이 프로그램을 실행할 경우 발생함
3) int a = 3, b = 0, c; c = a / b;를 실행한 경우 발생함
4) int *p = NULL; *p = 0;를 실행할 경우 발생함
5) Trap interrupt이 발생하면 현재 실행 중인 프로그램을 exit 상태로 전환하고 그 프로그램을 강제로 종료시킴

## 23 (p23) Feedback 스케줄링 — 올바른 것 2개 (복수선택)
1) SPN, SRT, HRRN은 짧은 작업의 프로세스를 우선적으로 실행하고자 하는 전략임
2) SPN, SRT, HRRN은 필요로 하는 프로세스의 서비스 시간을 미리 알고 있어야 적용 가능함
3) 실제 remaining time을 몰라도 SRT보다 더 뛰어난 효과를 내는 것이 Feedback 알고리즘임
4) 운영체제가 서비스 시간을 미리 쉽게 예측할 수 있기 때문에 SPN, SRT, HRRN의 활용도가 매우 높음

## 24 (p24) 운영체제의 목적 — 잘못된 것 2개 (복수선택)
1) 여러 프로세스를 동시에 실행시켜 processor의 이용률을 높인다.
2) 윈도우 창에서 수정하고자 하는 문서를 선택하고 더블클릭하면 해당 프로그램을 자동으로 실행시켜 준다.
3) 하드웨어가 발전하면 이를 지원하기 위해 운영체제도 함께 발전한다.
4) 하드웨어적 에러 발생은 사용자에게 통보해 줄 수 있지만 소프트웨어적 에러는 탐지할 수 없어 통보할 수 없다.
5) 메모리를 여러 프로세스에게 동적으로 할당해 주기 위해 가능하면 많은 메모리 compaction을 실시하도록 메모리를 관리한다.

## 25 (p25) Multiprogramming system — 틀린 것
1) 응답시간을 최소화하는 것이 주 목적임
2) 현재 실행중인 프로세스가 완료하거나 기다리던 데이터가 들어 올 때 process switch 발생
3) I/O 함수 호출시 장치에 데이터가 없을 경우 process switch 발생
4) 시분할처리 기능은 제공하지 않음
5) 여러 프로그램을 동시에 실행시키며 멀티태스킹이라고도 함

## 26 (p26) Optimal 교체 프레임

1) page fault 발생하지 않음  2) [3]  3) [2]  4) [0]  5) [1]

## 27 (p27) virtual memory system의 특성 3개 (공통 특성 포함, 복수선택)
1) Main memory의 크기가 동일할 경우 virtual memory는 real memory 시스템보다 더 많은 프로세스를 실행할 수는 없음
2) CPU 이용률을 더 향상시킬 수 있음
3) 메인 메모리보다 더 큰 프로그램도 실행 가능함
4) 프로세스 image는 메모리에 연속적으로 배치되어야 실행 가능함
5) 프로세스의 일부분만 메모리에 로드되어도 프로세스 실행 가능

## 28 (p28) 메모리 양 고정, 페이지 크기가 작아질수록 — 틀린 것 2개 (복수선택)
1) 페이지 크기와 상관없이 페이지 테이블을 위한 메모리 소비에는 큰 영향이 없음
2) 페이지 폴트율이 점점 높아짐
3) 프로세스당 많은 페이지가 메모리에 상주 가능함
4) 메모리의 프레임 크기가 작아지고 프레임 수는 증가함
5) 프로세스가 최근에 참조한 페이지들이 거의 대부분 메모리에 상주할 가능성이 높아짐

## 29 (p29) Time sharing system — 틀린 것 2개 (복수선택)
1) Response time을 최소화하는 것이 주 목적임
2) 유닉스와 MS Windows NT와 같은 서버시스템들은 이 범주에 속하지만 PC용 MS Windows는 여기에 포함되지 않음
3) 주어진 time quantum을 모두 소진하지 않아도 process switch 발생할 수 있음
4) 대화형 프로그램보다는 배치작업(batch jobs)들을 연속적으로 빠르게 실행시키고자 하는 시스템
5) I/O 함수 호출시 장치에 데이터가 없을 경우 process switch 발생

## 31 (p31) Interrupt handler가 하는 일이 아닌 것
1) 벡터링, 문맥저장, 문맥복구를 수행함
2) 제일 마지막 단계에서 scheduler() 함수를 호출함
3) 대기큐에서 기다리던 이벤트를 받은 프로세스를 대기 큐에서 ready 큐로 이동시킴
4) interrupt service routine 또는 device driver라고도 함
5) 이벤트를 받은 프로세스를 대기 큐에서 찾아 이벤트(데이터) 등을 전달함

## 32 (p32) 문서 편집기 '가' 입력 후 1초 쉬고 'ㄴ','ㅏ' 빠르게 입력 — 1초 쉰 이후 상태 변화
1) blocked -> ready -> running -> ready -> running -> blocked
2) blocked -> ready -> running -> running -> blocked
3) blocked -> ready -> running -> blocked -> ready -> running -> blocked
4) blocked -> ready -> running -> ready -> running -> ready

## 33 (p33) Round-robin — 올바른 것 2개 (복수선택)
1) I/O-bound 프로세스보다 상대적으로 불리한 CPU-bound 프로세스를 위해 virtual round-robin이 만들어 졌음
2) Virtual round-robin은 여러 개의 ready queue가 존재하며 프로세스는 한번 실행 때마다 다음 단계의 큐로 한 단계씩 내려감
3) CPU-bound 프로세스는 대부분 자신에게 주어진 time quantum을 모두 소진한 후에 processor를 반납함
4) I/O-bound 프로세스는 I/O 작업으로 인해 자신에게 주어진 time slice를 다 사용하지도 못한 채 processor를 반납해야 하는 경우가 종종 발생함

## 34 (p34) load control — 잘못된 것 2개 (복수선택)
1) 페이지 폴트율/프로세스의 수 상관관계 그래프에서 적절한 프로세스의 수는 무릎 높이에서 결정하는 것이 타당함
2) 오늘날의 대부분의 운영체제들은 시스템 내의 프로세스 수를 자동으로 조절해 주는 기능을 가지고 있음
3) 프로세스 수가 작아질수록 swapping을 위해 processor의 시간이 많이 소비됨
4) 프로세스 수가 아주 많아지면 thrashing으로 인해 processor의 시간이 많이 소비됨
5) 프로세스의 수가 줄어들수록 페이지 폴트율은 급격히 증가함

## 35 (p35) 메모리 보호(protection) — 맞는 것
1) 메모리 보호 기능은 run time보다는 compile time 때 제대로 작동할 수 있다.
2) 메모리 보호는 MMU가 있어야만 구현 가능하다.
3) 내 프로세스가 다른 프로그램 영역을 침범할 때 예외만 발생하고 강제 종료시키지는 않는다.
4) 다른 프로그램이 내 프로세스 영역을 침범할 때 내 프로그램도 일부 영향을 받을 수 있다.
5) 하드웨어의 보조 없이 운영체제의 순수 기능만으로도 충분히 구현할 수 있다.

## 39 (p39) swap out/in의 근본적인 이유

## 42 (p42) 프로세스 — 틀린 것 2개 (복수선택)
1) 프로그램 코드와 데이터, 그리고 PCB 등을 위한 메모리가 필요함
2) 현재 컴퓨터에서 실행되고 있는 프로그램을 프로세스라 함
3) 실행 시 arithmetic error/invalid instruction 등으로 비정상 종료될 수 있음
4) 로그인 또는 운영체제에 의해 새로운 프로세스가 생성되고 기존 프로세스에 의해 생성될 수는 없음
5) 하나의 프로세스를 관리하는데 필요한 정보를 담고 있는 것은 process information block이라 함

## 45 (p45) 메모리 재배치(relocation) — 틀린 것
1) 메모리 재배치가 있을 경우 논리주소를 실제주소로 변환하는 기능이 반드시 필요하다.
2) 디스크로 프로세스를 swap out한 후 다시 swap in할 때 재배치가 일어난다.
3) 메모리 재배치가 발생해도 프로그램에서 사용하는 포인터 변수의 주소 값은 영향을 받지 않는다.
4) 메모리 compaction할 때 재배치가 일어난다.
5) first-fit, best-fit, next-fit 알고리즘들을 사용하는 시스템에서는 페이징 기법을 사용하기 때문에 메모리 재배치가 필요 없다.

## 46 (p46) Dynamic memory partitioning 알고리즘 — 틀린 것
1) Best-fit은 계속해서 가장 작은 fragmentation들을 발생시킨다.
2) Next-fit은 마지막으로 할당한 메모리의 위치를 기억하고 있어야 한다.
3) 가장 구현하기가 쉽고, 빠른 알고리즘은 first-fit이다.
4) Worst-fit은 가장 큰 빈 블록에서 요청한 메모리 크기만큼의 영역을 할당해 준다.
5) 성능이 가장 좋은 알고리즘은 best-fit이다.

## 49 (p49) 용어 설명 — 올바른 것 2개 (복수선택)

2) Response time: 입력이 들어간 후 출력이 나올 때까지 소요된 시간
3) Deadline: 프로세스 실행을 완료해야 하는 만기 시간
4) Turnaround time: 단위시간당 처리를 끝낸 프로세스 개수

## 50 (p50) TLB 있는 paging 주소 변환 과정 순서
A) Page table을 참조하여 프레임 번호를 찾아 실주소로 변환함
B) Page table을 수정하고 fault가 발생한 프로세스를 재실행함

E) fault가 발생한 페이지를 메모리로 읽어 들이도록 디스크에 요청함
