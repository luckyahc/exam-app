## 1 (p1) 운영체제 설명 — 잘못된 것 (2점) — 정답 3
1) 응용프로그램의 실행을 제어하는 거대한 프로그램 또는 함수들의 집합이다.

4) 운영체제는 컴퓨터를 편리하게 사용하게 하고 자원을 효율적으로 관리한다.

## 27 (p27) Fixed memory partitioning — 틀린 것 2개 (3점) — 정답 2, 3
1) 아무리 작은 프로그램일지라도 하나의 partition 전체를 할당해 주어야 한다.
2) 구현이 쉽고 빠르지만 때때로 메모리 compaction을 수행해야 한다.
3) External fragmentation이 발생할 수 있다.
4) Equal-size partitions과 unequal-size partitions가 있다.
5) Unequal-size partitions의 경우 특정 크기의 partition은 사용하고자 하는 프로그램들이 많아 대기하는 일이 발생하지만 다른 크기의 partition들은 비어 있는 비효율적인 경우도 발생한다.

## 28 (p28) = 23-10 Dynamic partitioning(Buddy 제외) — 틀린 것 2개 — 정답 3, 4
1) 크기·개수 가변  2) placement policy로 사용 가능  3) best-fit에서는 external fragmentation 발생하지 않음  4) best-fit은 compaction 필요 없음  5) 때때로 compaction 필요

## 29 (p29) = 23-46 Dynamic partitioning 알고리즘 — 틀린 것 (1점) — 정답 5
1) Best-fit은 계속 가장 작은 fragmentation 발생  2) 가장 구현 쉽고 빠른 것은 first-fit  3) Next-fit은 마지막 할당 위치 기억  4) Worst-fit은 가장 큰 빈 블록에서 할당  5) 성능이 가장 좋은 알고리즘은 best-fit

## 37 (p37) = 23-19 basic paging system — 옳은 것 — 정답 4
1) 프로세스와 실제 메모리를 동일 크기로 분할한 것을 각각 frames와 pages라 한다.  2) 모든 page는 연속 공간에 배치  3) 페이지 테이블은 MMU가 만들고 관리  4) MMU 장치는 논리주소를 실제주소로 변화하며 메모리 protection 기능까지 제공한다.  5) 포인트 변수 주소 값은 실제 메모리 주소

## 38 (p38) = 23-27 virtual memory system의 특성 3개 — 정답 1, 2, 5
1) 메인 메모리보다 더 큰 프로그램도 실행 가능함  2) CPU 이용률을 더 향상시킬 수 있음  3) 프로세스 image는 연속 배치되어야 실행 가능  4) 같은 메모리 크기면 더 많은 프로세스를 실행할 수 없음  5) 프로세스의 일부분만 메모리에 로드되어도 실행 가능

## 42 (p42) 스레드와 프로세스로 구분된 시스템 — 올바른 것 2개 — 정답 1, 3
1) 프로세스는 자원의 할당 대상이며 자원의 소유주 역할을 함
2) processor 역시 하나의 자원이므로 자원의 소유주인 프로세스에게 할당 가능함
3) 프로세스는 메모리 보호 대상이기도 함
4) 스레드는 프로그래밍 언어에서는 제공되지 않으며 기반 OS에서만 제공되는 고급 프로그래밍 기능임

## 43 (p43) 프로세스 대비 스레드의 우수성 — 틀린 것 2개 — 정답 2, 4
1) 프로세스를 생성하는 시간보다 스레드를 생성하는 시간보다 짧다.
2) 종료시간은 실행을 종료해야 되므로 프로세스보다 스레드를 종료하는 것이 더 오래 걸린다.
3) 프로세스간 CPU 스위치보다 스레드간 CPU 스위치가 더 빠르다.
4) 프로세스간 통신은 인터넷을 통해 쉽게 할 수 있지만 스레드간 통신은 적절한 방법이 없다.

## 44 (p44) 여러 스레드의 동일 변수 동시 접근 — 틀린 것 2개 — 정답 1, 3
1) 여러 스레드가 동시에 동일한 지역변수를 수정하면 잘못된 결과가 나올 수 있음
2) 여러 스레드가 동일한 전역변수를 동시에 접근하면 잘못된 결과가 나올 수 있음
3) 동적으로 할당한 메모리는 MMU가 관리하기 때문에 여러 스레드가 동시에 접근해도 안전함
4) 함수 코드는 메모리 내 한 곳에만 존재하지만 읽기만 하므로 동시에 실행해도 안전함

## 45 (p45) 스레드 사용 이점 — 틀린 것 2개 — 정답 1, 2
1) 마우스와 키보드 작업은 백그라운드로, 이미지/동영상/애니메이션 등은 foreground로 나누어 작업 가능
2) 두 스레드가 서로 순서를 지키면서 정보를 주고 받으면서 일을 처리하는 비동기 처리가 가능함
3) 각 스레드마다 하나의 이미지를 담당하게 하여 여러 이미지들을 동시에 처리하게 하여 실행속도 향상 가능
4) 기능별로 분리하여 별도의 스레드로 나누어 프로그래밍할 수 있어 보다 복잡한 기능도 쉽게 구현 가능함

## 46 (p46) 스레드 시작 함수 작성 — 틀린 것 2개 — 정답 1, 4
1) 스레드의 실행 중 대기하게 하는 대표적인 함수들은 tree_search(), sort(), binary_search() 등이다.
2) loop 내에서는 반드시 대기하는 함수를 호출하는 시점이 있어야 함
3) 대부분 loop 문을 통해 동일한 작업을 반복 수행함
4) 모든 스레드의 시작 함수는 main() 함수처럼 특별히 지정해 주지 않아도 시스템에서 알아서 자동으로 호출해 줌

## 47 (p47) TCB에 저장하지 않는 것 2개 — 정답 2, 3
1) execution state  2) page table pointer  3) stack  4) thread context

## 48 (p48) 스레드와 TCB — 틀린 것 2개 — 정답 2, 4
1) 스레드의 실행 위치는 TCB의 context에 저장되므로 여러 스레드가 동일한 함수에 진입해도 각 스레드의 실행 위치를 정확히 저장하고 복구할 수 있음
2) 스레드의 전역변수, 힙 등은 각 스레드마다 별도로 메모리가 주어지므로 다른 스레드와 상관없이 안전하게 사용할 수 있음
3) 각 스레드는 별도의 스택을 가지므로 함수 내의 동일한 지역변수를 동시에 접근해도 안전함
4) 스레드는 실행코드, 전역변수, 힙, 열려진 파일이나 소켓 등과 같은 자원의 소유주 역할도 함

## 49 (p49) 지역변수·매개변수를 각 스레드 스택에 따로 저장할 수 있는 이유 — 올바른 것 2개 — 정답 1, 2
1) 지역변수와 매개변수는 나중에 컴파일러에 의해 스택 top에서 상대적으로 떨어진 위치 값으로 변수에 접근하도록 코드가 변경됨
2) 스택 top을 가리키는 레지스트는 SP이며 TCB context의 일부임
3) 각 스레드마다 PC를 가지고 있고 이 PC는 변수가 저장된 주소를 가지고 있으므로 따로 구분하여 관리할 수 있음
4) 모든 지역변수는 일반 레지스트에 저장이 가능하며, 이 레지스트를 통해 각 스레드마다 다르게 저장하는 것이 가능함

## 50 (p50) 스레드 생성 및 종료 — 틀린 것 2개 — 정답 2, 4
1) main 스레드를 제외한 스레드의 경우 반드시 프로그래머가 스레드를 생성하는 함수를 호출하여 생성해 주어야 한다.
2) 스레드를 생성하는 함수 호출 당시 스레드 시작함수를 지정하지 않고 추후에 별도로 시작함수를 호출해 주어야 한다.
3) main() 스레드는 주로 GUI의 입력 및 출력을 담당한다.
4) 스레드가 정상 종료하기 위해선 스레드 시작 함수에서 스레드 종료를 요청하는 특정 함수를 호출해야 한다.
5) 자바를 제외한 대부분의 시스템에선 main() 함수에서 리턴하면 모든 스레드들이 자동 종료되면서 프로그램이 종료한다.
