# 심리학개론 계획 (1단계: 과목 생성 + 서술형 타입 + 1~3장)

작성: 2026-10-16. 원천자료: [`source-ch01-03.md`](./source-ch01-03.md)(교재 사진 전사본 + 끝의 "부록: 용어 정의 (보충)"). 4~7장은 원천자료가 오면 추가한다.

- 교재: 마이어스의 심리학개론. 시험 범위 1~7장(서막 제외). 시험 형식: 선택형 / 단답형 / 서술형.

- 과목 id `psychology`(표시명 심리학개론). 단원은 지금 ch01~ch03만(4~7장은 나중에 추가).

## 1. 근거 규칙

- 용어 표기는 원천자료의 교재 표기를 그대로 쓴다(예: 도약대, 선도성 대 죄책감, 가짜약 효과, 이중은폐 절차, 무선할당). 흔한 다른 표기는 해설에 괄호로만 병기.
- 원천자료에 없는 내용(연구자, 수치, 예시, 이론 세부)을 쓰면 문장마다 "(보충)"을 붙이지 않고, 해설 끝에 근거 한 줄로 한 번만 표기한다(2026-10-16 변경). 원천자료에 없는 수치·연도를 정답 근거로 쓰지 말 것.
  - 형식: `근거: 교재 표 3.1`(교재만) / `근거: 교재 표 3.1 + 보충`(교재와 보충이 섞임) / `근거: 교재 본문 + 보충` / `근거: 교재 용어 + 보충(표준 정의)`(용어 박스의 용어를 부록 정의로 판단).
  - 데이터: `why(정답, 오답, 연결, 근거)`(`data/subjects/psychology/helpers.ts`) — 화면은 근거 줄을 해설 아래 작게 따로 보인다.
  - 정답 판단의 근거가 보충뿐인 문항(정답 이유에 교재 표·그림·본문 근거가 없는 것)은 내용을 그대로 두고 목록만 보고한다.
- 교재 원문 문장 복제나 교재 사진 사용 금지. 문제와 해설은 직접 작성.
- examBasis: 용어 박스·표에서 나온 문제는 printed-emphasis. 그 밖에는 기존 스키마 규칙을 따른다(스키마를 먼저 확인할 것).
- (적용 메모) 문제·해설·모범답안은 원천자료 끝의 부록 정의를 기준으로 쓴다. 부록은 전부 보충이므로, 부록 정의를 쓴 문항은 근거 줄에 "+ 보충"을 넣는다. 본문(교재 전사)과 부딪히면 본문이 우선.
- (적용 메모) 스키마: `exam: true`면 `examBasis` 필수, ⭐ 문항은 `summary`(120자 이하) 필수(`data/subjects/contentQa.test.ts`). ⭐(printed-emphasis) = 표(1.2, 2.1, 3.1, 3.2, 3.3, 그림 3.14)를 묻는 문항과 용어 박스의 용어 자체(정의·이름)를 묻는 문항. 사례 적용·비교·서술형 중 표가 아닌 것은 `exam: false`.
- (적용 메모) 문항 안에서 상황을 설정한 가상 사례(인물·장면)는 문제 장치이므로 보충으로 세지 않는다. 사실 주장(연구자·수치·이론 세부)만 보충으로 센다.

## 2. 문제 유형

- 선택형: 기존 mcq / multi / ox / match / order 사용. 자동 채점.
- 단답형: 기존 타입 중 "독립 문항 + 인정 답안 여러 개 + 공백·대소문자 무시" 채점이 되는 것이 있으면 재사용하고, 없으면 short 타입을 추가. 인정 답안에는 교재 표기와 흔한 동의어(예: 위약 효과)를 모두 넣는다.
  - → **blank 재사용**: `text: "답: {{0}}"` 한 칸, `blanks[0].accept`에 인정 답안 여러 개. 채점은 NFKC·소문자·모든 공백 제거 후 비교(`lib/qtypes/_shared/textMatch.ts`).
- 서술형: 기존에 자기채점형 타입이 있는지 먼저 확인. 없으면 essay 타입을 추가한다.
  - → 없어서 **essay 추가**(`lib/qtypes/essay.ts`, `components/qtypes/Essay.tsx`).
  - textarea로 입력 → [제출]을 누르면 "내 답"과 "모범답안"을 나란히 표시하고, 아래에 채점 포인트 체크리스트(3~5개)를 보여준다.
  - 정답·오답을 기록하지 않는다. 정답률·오답노트·약점 통계에서 제외하되, "풀었음"만 기록한다(기존 통계 로직이 깨지지 않게, 관련 테스트 추가).
    - → 채점 결과 `selfCheck: true`, 기록 `progress[id].selfCheck: true`(정답 수 0, lastScore null, 오답노트 없음). `summarize`·`generatedAttempts`·세션 결과 집계에서 빠진다.
    - → 풀이 상태는 별도 상태 **"제출함"**(`submitted`, 맞힌·틀린 문제가 아님 — 문제 목록에 "제출함(서술형)" 탭). ⭐ 달성도에서는 분모·분자 모두 제외, 단원·과목 진도(푼 문제 수)에는 포함(2026-10-16 변경).
  - 데이터: modelAnswer(3~6문장), keyPoints: string[].

## 3. 문제 구성 (1~3장, 총 약 120문항: 1장 35 / 2장 45 / 3장 40)

- 유형 비율: 선택형 55% / 단답형 25% / 서술형 20%.
- 선택형 안에서: 사례 적용형(상황 → 개념 고르기)을 가장 많이, 그다음 비교·구분, 정의·인물 암기, 순서·단계 순.
- 원천자료의 표 6개(1.2, 2.1, 3.1, 3.2, 3.3, 그림 3.14)는 각각 최소 3문항(선택형·단답형·서술형 섞어서).
- "기억해야 할 용어"는 장별로 빠짐없이 최소 1회 이상 문제나 보기에 등장시킨다. 커버리지 표를 docs/psychology/coverage.md 에 작성.
- 서술형은 맥락 이해형으로: "A와 B를 비교하라", "사례를 이론으로 설명하라", "연구 설계의 문제점을 지적하라" 등.
- 모든 문항의 해설에는 정답 이유 + 오답 보기가 틀린 이유 + 같은 장 안에서 관련된 개념 1줄(맥락 연결)을 넣는다.
  - → 해설 형식: "정답: … 오답: … 연결: …" + 끝에 "근거: …" 한 줄(`data/subjects/psychology/psychology.test.ts`가 검사).

## 토큰 절약 규칙

- 원천자료는 처음에 한 번만 전체를 읽는다. 이후에는 필요한 절만 grep/부분 읽기.
- 기존 코드·스키마는 grep으로 필요한 부분만 찾는다. 관련 없는 과목 데이터와 폴더는 열지 않는다.
- 문항은 장별 파일에 바로 쓴다. 쓴 내용을 채팅에 다시 출력하거나 파일을 다시 읽어 검토하지 않는다(검증은 테스트로).
- 파일 수정은 필요한 부분만 편집한다. 큰 파일 전체를 다시 쓰지 않는다.
- 테스트는 새 타입 관련 테스트만 중간에 1번, 전체 test·타입체크·빌드는 마지막에 1번. 실패하면 실패한 테스트만 다시 실행한다.
- 브라우저 확인과 dev 서버 실행은 하지 않는다.
- 진행 중 설명은 하지 말고 결과만 보고한다. 보고는 6단계 형식, 15줄 이내.
