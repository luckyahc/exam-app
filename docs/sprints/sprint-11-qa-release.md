# Sprint 11 — QA, 접근성 점검, 배포 준비

## 목표

전체 완료 조건(원본 §10, [`00-overview.md`](../00-overview.md))을 최종적으로 만족시키고 Vercel 배포 가능 상태로 마무리한다.

## 선행 조건

- Sprint 1~10 전부 완료

## 작업 항목

### 접근성 / 다크모드

- [ ] 모든 화면·컴포넌트(표, 코드/수식 블록, 구문 강조 토큰, 과목 색, 그래프 SVG 포함)를 라이트/다크 양쪽에서 대비 점검
- [ ] 정답/오답 표시가 색상 단독이 아닌 아이콘+텍스트로 되어 있는지 전체 재점검
- [ ] 키보드 단축키(1~5, Enter, ←/→)가 모든 문제 유형에서 일관되게 동작하는지 점검
- [ ] 포커스 표시(outline) 누락 컴포넌트 점검

### 모바일 반응형

- [ ] 320~400px 폭에서 모든 화면 깨짐 없는지 확인
- [ ] `order`/`trace` 유형 모바일 대체 입력(↑↓ 버튼, 드롭다운) 동작 재확인

### 테스트 / 빌드

- [ ] `npm run lint` 통과
- [ ] `npm test` (Vitest 전체: 문제 유형 채점 + `lib/sim/*/` 전 과목 시뮬레이터 + 데이터 무결성 + 마이그레이션/백업) 통과
- [ ] `data/subjects/integrity.test.ts`의 챕터별 최소 문항 수 검사를 **경고 → 실패 조건**으로 전환
- [ ] `npm run build` 통과, 빌드 산출물에 서버/DB/환경변수 의존 없는지 확인
- [ ] 로컬에서 `next build && next start`로 프로덕션 모드 수동 점검

### 콘텐츠 최종 검수

- [ ] `content-checklist.md` 전체 항목(과목별) 체크 완료 상태 확인
- [ ] 챕터별 최소 문항 수 재확인: OS(Ch02≥50/Ch03≥80/Ch07≥80/Ch08≥120), 데이터 통신(Ch01≥57/Ch02≥106 — [`coverage-matrix.md`](../coverage-matrix.md))
- [ ] 서술형 문제가 섞여 있지 않은지 전체 데이터 스캔

### README / 배포

- [ ] `README.md` 작성: 로컬 실행 방법, 문제 추가 방법(스키마 설명 + 예시), **과목 추가 방법**(레지스트리 + `data/subjects/{과목}/`), **문제 유형 추가 방법**(레지스트리 2곳), Vercel 배포 방법(GitHub 연동 → Import → Deploy)
- [ ] Vercel에 설정 파일 없이 `Import` 했을 때 빌드가 성공하는지 확인 (환경변수/빌드커맨드 커스터마이징 불필요 상태)

## 완료 기준 (DoD) — 전체 프로젝트 완료 조건과 동일

1. 과목 → 챕터 분리(OS 4개 챕터 + 데이터 통신 2개 챕터) + 유형/⭐/토픽 필터로 풀이 가능, 오답노트·북마크·통계 과목별 + 전체 보기
2. 서술형 없음
3. 다크모드 정상(FOUC 없음, 전체 대비 충분)
4. 생성기·시뮬레이터 테스트 전부 통과
5. `npm run lint && npm test && npm run build` 모두 통과
6. Vercel에서 설정 없이 배포 가능
