## 이 문서와 다르게 한 부분

1. **네트워크 차단·속도 제한을 개발자 도구 대신 로컬 프록시로 재현**: 브라우저 확장으로는 개발자 도구(Network 탭)를 열 수 없다. `next start`(3123) 앞에 작은 프록시(3124·3125, 작업 폴더 밖 임시 파일)를 두고 엔진 파일에 503을 돌려주거나 800 KB/s로 흘려보냈다. 엔진 파일은 1년 캐시라 출처(포트·호스트)를 바꿔 빈 캐시로 시작했다
2. **엔진 사용성 수정 3건(문서에 없던 고침)**: 실패 화면에 "다시 시도" 버튼이 없었다(Sprint 13에도 요구 없음) → 추가. wasm 내려받기가 실패하면 Pyodide가 오류 없이 멈춰 실패 화면이 180초 뒤에 떴다 → Worker가 엔진 파일 응답 실패를 바로 알리고 실패한 Worker는 버린다. 휠 내려받기 실패 뒤 다시 시도가 openpyxl 설치를 건너뛰던 문제 → 휠 설치 뒤에 기록
3. **엔진 재사용은 고칠 것이 없었다**: 이미 앱 전체에서 Worker 하나를 쓴다. Sprint 16의 "두 번째에도 17초"는 매번 페이지를 새로 불러온 확인 방법 탓이었다 — 단위 테스트(`lib/engine/client.reuse.test.ts`)를 추가해 고정
4. **대조 기록 자동 검사는 데이터과학만**: `records.test.ts`의 표 형식 검사는 데이터과학 강의 기록에만 있다. OS·데이터 통신 기록은 형식이 다른 수동 문서라, 모든 문항 id가 기록에 있는지만 임시 스크립트로 확인했다(누락 0)
5. **기록 왕복은 단위 테스트로 확인**: 세 과목(데이터과학 포함) 내보내기 → 데이터과학만 초기화 → 가져오기(합치기) 테스트를 `lib/storage/recordsStore.test.ts`에 추가. 브라우저에서 파일 내려받기·올리기 왕복은 하지 않았다(아래 6)
6. **화면 점검(3과목 × 14화면 × 375/768/1280 × 라이트/다크)·키보드 풀이는 끝내지 못했다**: PC 여유 메모리가 0.1~0.4 GB까지 떨어져 Chrome이 탭을 다시 불러오거나 렌더러가 멈췄다(84조합 중 4조합에서 중단, 넘침·테마 문제 0). 시스템이 프록시·서버 백그라운드 작업도 한 번 종료했다
