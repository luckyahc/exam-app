```text
           결정 방식(Decision Mode)
 Nonpreemptive (비 선점형) 스케줄링
   인터럽트에 의한 process switch 없음
   일단 프로세스가 실행되면, 종료되거나 I/O 함수 호출로 인해
    blocked 될 때까지 계속 실행(더 높은 우선순위 프로세스가 있어도)
                       단순히 새 프로세스가 도착했다고 스케줄링하지 않음

   현재 실행중인 프로세스가 종료/blocked되면 다시 스케줄링 함
 Preemptive (선점형) 스케줄링
   인터럽트에 의해 process switch 가능
   현재 실행 중이던 선점 당한 프로세스는 다시 Ready 상태가 됨
   인터럽트 끝에 scheduler 호출 -> 다른 선점한 프로세스 실행
   한 프로세스의 장기간 CPU 독점 방지
   현재 돌던 프로세스가 종료/blocked, 새 프로세스가 도착, 또는
    time quantum 소진(0.1초 동안 실행)하면 다시 스케줄링 함
   현재 돌던 프로세스보다 높은 우선순위 프로세스가 도착/또는 주
    어진 time quantum이 소진되자 마자 스케줄링하면 preemptive
```

## p.18

```text
  서비스 시간 추정 (Estimating Service Time)
 SPN·SRT·HRRN은 예상 서비스(실행) 시간이 필요함
     과거 CPU burst(CPU에서 쉬지 않고 일하는 시간 양) 이력으로 다음 실행 시간을 예
       측함; CPU burst -> I/O burst -> CPU burst -> I/O burst의 반복
     T(n) = n번째 실제 실행 시간, S(n) = n번째 예측 시간

 단순 평균 (Simple Averaging)
     과거 관측값을 모두 같은 가중치로 평균 → 오래된 이력이 최근 변화를 가림

 지수 평균 (Exponential Averaging)
     S(n+1) = α × T(n) + (1 - α) × S(n)   (0 < α < 1)
     최근 관측값일수록 가중치가 큼
      과거값은 (1-α)의 거듭제곱으로 빠르게 감소
     α가 클수록 최근 변화에 민감(빠른 반응), 작을수록 과거를 더 반영(안정적)
```

## p.26

```text
                    세 지표의 의미
 반환시간(Tr) = 완료 − 도착 = 대기시간 + 서비스시간(Ts)
     작업이 끝나기까지의 총 소요 (기다림 + 실행)
 대기시간(Tw) = 반환시간 − 서비스시간 = (Tr − Ts)
     순수하게 큐에서 기다린 시간
     서비스는 고정이라 스케줄러가 줄이는 대상
 정규화 반환시간(Tr/Ts) = 1 + 대기시간/서비스시간 (최소 1)
     실행량 대비 상대적 지연
     짧은 작업이 오래 기다리면 값이 크게 튐 (공정성 판단)
     예: Ts = 1이고, Tw = 1 또는 Tw = 10인 경우,
      정규화 반환시간은 1+1/1 또는 1+10/1
 관계: Tr = Tw + Ts, 정규화 = 1 + Tw/Ts
```
